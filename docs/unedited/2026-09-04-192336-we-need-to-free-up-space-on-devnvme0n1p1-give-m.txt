  1. Confirm what the partition is mounted as and how full it is:
  df -h /dev/nvme0n1p1
  2. Rank the top-level directories on that filesystem. -x keeps du on this one
  filesystem so other mounts don't pollute the numbers (run with sudo so nothing
  is skipped; substitute the mount point from step 1 if it isn't /):
  sudo du -xh -d1 / 2>/dev/null | sort -rh | head -20
  3. Recurse into whichever directory dominates, same command one level deeper:
  sudo du -xh -d1 /<biggest-dir> 2>/dev/null | sort -rh | head -20
  3. Repeat until you hit the actual consumers. On this machine the usual
  suspects are /nix/store, /var/log/journal, VM disk images, and ISO downloads.
  4. Hunt individual large files directly, in parallel with the drill-down:
  sudo find / -xdev -type f -size +1G -exec ls -lh {} \; 2>/dev/null
  4. Drop to +500M if that returns too little.
  5. If ncdu is available (or via nix run nixpkgs#ncdu), it replaces steps 2–3
  with one interactive pass:
  sudo ncdu -x /
  6. If /nix/store is the bulk, reclaim with:
  sudo nix-collect-garbage -d
  6. -d also deletes old system generations, which removes rollback targets —
  skip the flag if you want to keep them. Deleted files held open by running
  processes don't free space until the process exits; sudo lsof +L1 lists those.

❯ what is the best tool to compact an iso                                       

● zstd -19 --long=31 <file>.iso — best speed-to-ratio for hosting and downloads,
  and decompresses fast on the other end. xz -9 shaves a bit more at a much
  slower compress.

  A NixOS installer ISO stores its payload in an already-compressed squashfs, so
  either tool will only claw back a modest amount. The real lever is rebuilding
  the ISO with less in it (smaller closure), if the size matters at rest and
  off the wire.

❯ it's a qcow2 file actually                                                    

● virt-sparsify (from libguestfs, nix run nixpkgs#libguestfs-with-appliance… or
  nix shell nixpkgs#guestfs-tools):

  virt-sparsify --compress vm.qcow2 vm-compact.qcow2

  It reads the filesystems inside the image, drops the unused blocks, and writes
  a compressed copy. The VM must be shut down while it runs, and it needs
  scratch space roughly the size of the image.

  If virt-sparsify isn't available, the manual equivalent: run fstrim -av inside
  the guest, shut it down, then

  qemu-img convert -O qcow2 -c vm.qcow2 vm-compact.qcow2
